# Workflow Documentation — Orto-N-L-M / Ортона-AI

**Обновлено:** 27 октября 2026

Этот документ разделяет текущий веб-контур продукта и исторический Telegram workflow. Он описывает архитектурные роли, но не подтверждает состояние workflow на сервере: активность и точную версию следует проверять непосредственно в рабочем n8n.

## 1. Текущий веб-контур

Основной пользовательский путь:

```text
Должность → Процесс / Process JSON → Инструкция
                              ↓
                         Обучение
                              ↓
                             Тест
                              ↓
                           Результат
```

- **Web UI:** Ортона-AI (React / Vite).
- **API:** FastAPI.
- **Хранилище:** PostgreSQL.
- **AI-оркестрация:** n8n и OpenAI API в соответствующих сценариях.

Доступные пользовательские контуры включают управление должностями и инструкциями, AI-интервью, формирование Process JSON, обучение и тестирование. Владелец проекта подтверждает, что основные сценарии работают в production.

## 2. Исторический Telegram workflow

В репозитории может находиться экспорт `Orto-N Learning Manager (33).json` и связанная документация. Это экспорт раннего Telegram-контура, включавшего:

- Telegram Trigger и нормализацию входящих сообщений;
- маршрутизацию меню;
- AI-интервью и сохранение состояния;
- обработку вложений;
- формирование инструкций и тестов;
- отправку результатов через Telegram.

Данные о числе узлов, модели и статусе active относятся к указанному экспорту на дату его фиксации. Они **не подтверждают**, что именно эта версия активна на production n8n в настоящее время.

## 3. Process JSON

Process JSON является каноническим источником данных о процессе. Производные материалы, такие как инструкции и тесты, строятся на его основе.

## 4. База знаний и «Задать вопрос»

Корпоративная база знаний пока не сформирована. Поэтому полноценный поиск по базе знаний, RAG и универсальные ответы на вопросы по корпоративным документам не считаются реализованными. Эти возможности должны появиться после подготовки и проверки источника знаний.

Не путать эти ограничения с работающими сценариями интервью, генерации инструкций и тестирования.

## 5. Безопасность экспорта

Перед публикацией или коммитом n8n workflow необходимо проверить HTTP Request URL, headers, credentials и параметры узлов на наличие live Telegram-токенов, API keys и других секретов. В публичном репозитории должны находиться только обезличенные экспорты без действующих credentials.

## 6. Правило актуализации

При изменении production workflow:
1. получить экспорт непосредственно из рабочего n8n;
2. удалить секреты, не меняя бизнес-логику;
3. обновить описание и дату экспорта;
4. отдельно отметить, является ли workflow текущим, историческим или вспомогательным.
