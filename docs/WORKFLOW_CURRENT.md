## Контуры

### Telegram

`Telegram Trigger → Input Gateway → Session Router → Message Type Router → Navigation / media branches`

### Интервью

`Create Interview Session → Interview Agent → Parse Agent Response → Normalize Interview → Save Interview → Get Saved Process → Instruction Generator → HTML → Telegram`

### Вложения

Скриншоты/фото привязываются к конкретным шагам Process JSON. `Prepare HTML Attachments` использует сохранённые пути и метаданные файлов.

### Руководитель

`Должности` и `Инструкции`.

Для должностей реализованы добавление, редактирование и удаление с подтверждением. При удалении должности сначала удаляются связанные процессы.

### Стажёр

`Обучение → инструкция → Тестирование → проверка → HTML-результат`.

Тест генерируется только по Process JSON, варианты перемешиваются с сохранением правильного ответа, состояние сохраняется в PostgreSQL.

### Стажёр: веб-интерфейс

Контур обучения в веб-интерфейсе идёт по канонической цепочке:

```text
Должность → Процесс → Process JSON → Инструкция → Тест → Результат
```

- список инструкций строится по должности стажёра (`GET /processes`);
- тест формируется только из `process_json` выбранной инструкции (`POST /ai/test`, n8n `action=test`), каждый вопрос приходит с ровно четырьмя уникальными вариантами ответа и ровно одним правильным;
- результат сохраняется в PostgreSQL через `POST /test-results` (таблица `test_results`) и восстанавливается при следующем входе через `GET /test-results`;
- зачёт — от 80% правильных ответов; порог отдаёт backend в поле `pass_percent`, фронтенд его не дублирует.

Права: руководитель работает с процессами любой должности, специалист и стажёр — только со своей должности.

Отметка «изучено» хранится в PostgreSQL (`learned_instructions`, эндпоинты `POST /learned-instructions` и `DELETE /learned-instructions/{process_id}`), поэтому прогресс сохраняется между сессиями.

### Руководитель: результаты тестов

Раздел `Результаты тестов` показывает журнал всех попыток тестирования сотрудников:

```text
Сотрудник → Должность → Инструкция/Процесс → Попытка → Результат
```

- каждая попытка — отдельная запись в `test_results`, повторные прохождения не перезаписывают предыдущие;
- отображаются сотрудник, должность, инструкция, процент, правильные ответы из общего числа, статус и дата/время;
- фильтры по сотруднику и должности работают совместно и применяются на backend (`GET /manager/test-results?user_id=&position_id=`), а не в браузере;
- доступ только для роли `manager` (эндпоинт защищён `require_role("manager")`).

### Ветка теста в n8n

Контур теста используется существующий: `Action Router → action="test" → Prepare Test Input → AI Test Generator → Parse Test Response`.

В узле `Prepare Test Input` исправлен вход: он читает `$json.body ?? $json` (как соседние `Prepare *` узлы). Ранее узел обращался к `$json.process_json` напрямую и падал с ошибкой `process_json is required`, потому что webhook передаёт данные в `body`. Архитектура workflow не менялась.

## Важная деталь экспорта

В workflow есть три HTTP Request узла, которые обращаются к Telegram Bot API и содержат токен непосредственно в URL. Это часть текущего рабочего экспорта.

Поскольку репозиторий публичный, живой токен намеренно не помещается в GitHub. Необходимо хранить его только в рабочем окружении n8n и не копировать в публичные файлы.

## Источник истины

Для точного восстановления workflow используется исходный экспорт n8n, загруженный в проект. Документация GitHub фиксирует архитектуру и состояние, но не подменяет рабочий секретный экспорт.
