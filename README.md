# Orto-N-L-M

> AI-система для обучения сотрудников, сбора экспертизы и формирования корпоративной базы знаний.

Orto-N-L-M превращает практический опыт сотрудников в структурированные описания рабочих процессов, сохраняет их как канонический **Process JSON** и автоматически формирует на его основе обучающие материалы и инструкции.

Проект разработан как production-oriented workflow на **n8n + PostgreSQL + Telegram + OpenAI**.

---

## 🎯 Что решает система

Вместо того чтобы вручную собирать инструкции у сотрудников, система проводит интервью прямо в Telegram:

```text
Сотрудник
   ↓
Telegram
   ↓
AI-интервью
   ↓
Описание рабочего процесса
   ↓
Process JSON
   ↓
PostgreSQL
   ↓
Инструкция / обучающий материал
   ↓
Telegram
```

Главная идея проекта — **отделить знания от их представления**. Process JSON является каноническим источником данных, а инструкции и другие обучающие материалы являются производными представлениями.

## 🚀 Что уже работает

### Интервью сотрудника

- запуск интервью через Telegram;
- последовательное AI-интервью;
- определение должности сотрудника;
- сбор списка рабочих процессов;
- выбор конкретного процесса для подробного описания;
- пошаговое уточнение процесса: действия, инструменты, проверки, решения, проблемы и критерии завершения;
- завершение интервью и сохранение результата;
- сохранение состояния интервью в PostgreSQL;
- формирование Process JSON.

### Голос и визуальные материалы

- голосовые ответы сотрудника;
- автоматическая транскрибация;
- возможность запросить обезличенную фотографию или скриншот;
- обработка визуальных материалов как части интервью;
- отдельное предупреждение о необходимости удалить персональные и конфиденциальные данные перед отправкой.

### Управление процессами по должности

Реализована привязка сохранённых процессов к должности:

```text
Telegram user
      ↓
Последняя завершённая сессия интервью
      ↓
Должность сотрудника
      ↓
position_id
      ↓
Процессы этой должности
```

В меню специалиста появился раздел **«Мои процессы»**. Он показывает только процессы, связанные с должностью текущего специалиста.

Фактически проверенный сценарий:

```text
Специалист
   ↓
Мои процессы
   ↓
Администратор
   ↓
Приём звонков
   ↓
список процессов администратора
```

Таким образом, специалист не получает общий каталог чужих процессов.

### Менеджерский контур

Реализован отдельный интерфейс руководителя:

```text
Руководитель
   ↓
Проверить список инструкций
   ↓
Выбор должности
   ↓
Список инструкций должности
   ↓
Получение готового файла
```

Доступ к разделу руководителя ограничен whitelist разрешённых Telegram-пользователей.

Выдача инструкций реализована без участия AI: система получает данные из PostgreSQL, формирует динамические кнопки и отдаёт готовый файл.

## 🧩 Архитектура

Основной workflow построен вокруг единого входного контракта и разделения транспортной и бизнес-логики.

```text
Telegram Trigger
       ↓
Input Gateway
       ↓
Interview Session Router
       ↓
Message Type Router
       ├── Text / Callback
       │       ↓
       │   Navigation Router
       │       ↓
       │   Interview Agent / Navigation
       │
       ├── Voice
       │       ↓
       │   Telegram File
       │       ↓
       │   Speech-to-Text
       │       ↓
       │   Interview Agent
       │
       └── Photo / Screenshot
               ↓
           File Processing
               ↓
           Interview Agent

Interview Agent
       ↓
Process JSON
       ↓
PostgreSQL
       ↓
Knowledge / Instruction Generator
       ↓
File
       ↓
Telegram
```

### Навигация

Текущий пользовательский контур разделён на роли:

- 👨‍🔧 **Специалист**
  - 📝 Пройти интервью
  - 📂 Мои процессы
- 👨‍💼 **Руководитель**
  - 📋 Проверить список инструкций
  - ⚙️ Настройки
- 🎓 **Стажер**
  - отдельный контур обучения и тестирования.

Маршрутизация выполняется детерминированно через `Navigation Router`, `If` и `Switch`. AI не используется для принятия навигационных решений.

## 🗄️ Данные

Основные сущности PostgreSQL:

### `positions`

Справочник должностей.

### `processes`

Хранит:

- должность (`position_id`);
- название процесса;
- цель процесса;
- полный Process JSON.

### `interview_sessions`

Используется для управления жизненным циклом интервью и сохранения состояния сессии.

После завершения интервью должность сохраняется в состоянии сессии и используется для определения персонального списка процессов специалиста.

### `files`

Метаданные файлов, связанных с процессами и обучающими материалами.

## 📐 Process JSON

Структурированный формат знаний является каноническим источником проекта.

Принцип:

> **Сначала знания, потом представление.**

Это позволяет независимо создавать:

- рабочие инструкции;
- обучающие материалы;
- тесты;
- справочные материалы;
- другие форматы корпоративной базы знаний.

---

## 🔐 Доступ и роли

Ролевая модель реализуется на уровне workflow.

Особое правило — раздел руководителя доступен только разрешённым Telegram-пользователям. Для остальных пользователей этот маршрут закрыт.

При этом специалист работает только со своим контуром процессов: список **«Мои процессы»** фильтруется по должности, определённой из сохранённой сессии интервью.
