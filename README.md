# Orto-N-L-M

> AI-система для обучения сотрудников, сбора экспертизы и формирования корпоративной базы знаний.

Orto-N-L-M превращает практический опыт сотрудников в структурированный **Process JSON**, сохраняет его в PostgreSQL и использует как канонический источник для инструкций, обучения и тестирования.

## Текущий рабочий контур

```text
Telegram
   ↓
Input Gateway
   ↓
Session / Message Routing
   ├── Интервью специалиста
   │      ↓
   │   Interview Agent
   │      ↓
   │   Process JSON
   │      ↓
   │   PostgreSQL
   │      ↓
   │   Instruction Generator
   │      ↓
   │   HTML / Telegram
   │
   ├── Руководитель
   │      ↓
   │   Должности / Инструкции
   │      ↓
   │   PostgreSQL
   │      ↓
   │   готовый HTML-файл
   │
   └── Стажёр
          ↓
       Обучение
          ↓
       Тестирование
          ↓
       Результат теста
```

## Что подтверждено рабочим тестированием

### Специалист
- запуск интервью;
- полноценное адаптивное интервью до 15 содержательных вопросов;
- запрос скриншотов/фото при реальной необходимости;
- обработка голосовых ответов и транскрибация;
- формирование Process JSON;
- сохранение процесса и должности в PostgreSQL;
- генерация и отправка HTML-инструкции;
- `📂 Мои процессы` с фильтрацией по должности.

### Руководитель
Меню руководителя содержит только:
- `👤 Должности`;
- `📚 Инструкции`.

Работают:
- список должностей;
- добавление;
- редактирование названия;
- удаление с подтверждением;
- удаление связанных процессов/инструкций перед удалением должности;
- список инструкций по должности;
- получение готовой инструкции без участия AI.

### Стажёр
Работают:
- выбор должности;
- список инструкций;
- получение инструкции;
- генерация теста по Process JSON;
- ровно 4 варианта ответа на вопрос;
- механическая проверка ответов;
- сохранение состояния теста в PostgreSQL;
- перемешивание вариантов с сохранением правильного ответа;
- итоговый HTML-результат и отправка файла в Telegram.

## Process JSON

Process JSON — главный источник знаний системы. Производные представления не должны изменять факты, полученные от эксперта.

```json
{
  "metadata": {
    "interviewee": "",
    "role": "",
    "position": "",
    "employee_position": "",
    "process": ""
  },
  "goal": "",
  "steps": [
    {
      "id": "step1",
      "title": "",
      "instruction": "",
      "expected_result": "",
      "attachments": [],
      "exceptions": [],
      "tips": [],
      "notes": ""
    }
  ]
}
```

## Актуальный workflow

Последний рабочий экспорт находится в проектных материалах как `Orto-N Learning Manager (33).json` (75 узлов, активный workflow). В репозитории хранится документация и версия проекта; полный экспорт workflow содержит рабочие Telegram HTTP Request URL с токеном бота, поэтому **живой токен в публичный репозиторий не публикуется**.

При этом структура workflow, имена узлов, связи и версии нод фиксируются документацией ниже. Для восстановления на сервере используется исходный экспорт из n8n.

## Безопасность

Публичный GitHub-репозиторий не должен содержать действующий Telegram Bot Token или другие секреты. Это единственное отличие публичной копии от рабочего экспорта: функциональную логику не меняем.
