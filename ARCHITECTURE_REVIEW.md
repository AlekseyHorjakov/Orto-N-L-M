# Реализованные компоненты

## Telegram Trigger

**Статус**

✅ Завершен.

**Ответственность**

Получение входящих Update от Telegram.

---

## Input Gateway

**Статус**

✅ Завершен.

**Ответственность**

Преобразование Telegram Update в Unified Message.

Полностью соответствует AI_CONTEXT.

---

## Message Type Router

**Статус**

✅ Завершен.

**Ответственность**

Определение типа сообщения.

Поддерживаются:

- text
- callback
- voice
- photo
- document

Компонент полностью соответствует принципу единственной ответственности.

---

## Telegram Response Router

**Статус**

✅ Завершен.

**Ответственность**

Выбор способа ответа Telegram.

Используются:

- sendMessage
- editMessageText

---

## Navigation Router

**Статус**

✅ Завершен.

**Ответственность**

Навигация пользователя по системе.

Отвечает исключительно за:

- отображение меню;
- обработку выбора пользователя;
- маршрутизацию к Business Workflow.

---

## Interview Session Router

**Статус**

✅ Реализован.

**Ответственность**

Определение наличия активной сессии интервью.

При наличии активной сессии сообщение сразу передается Interview Agent.

При отсутствии активной сессии сообщение передается в Navigation Workflow.

---

## Parse Agent Response

**Статус**

✅ Реализован.

**Ответственность**

Преобразование строкового JSON, возвращаемого Interview Agent, в объект Workflow.

---

## Interview Agent

**Статус**

✅ Подключен.

Interview Agent является центральным компонентом системы интервьюирования.

Вся логика проведения интервью полностью находится внутри Interview Agent.

Workflow не управляет последовательностью вопросов.

Interview Agent возвращает ответ в формате Unified Agent Response v1.0.

Prompt полностью соответствует утвержденной архитектуре проекта.

# Архитектурные замечания

По состоянию на 05.08.2026 критических архитектурных замечаний не выявлено.

Во время разработки были реализованы следующие архитектурные изменения:

- Navigation Router отделен от Interview Workflow;
- реализован Interview Session Router;
- внедрен Unified Agent Response;
- внедрен Parse Agent Response;
- Interview Agent полностью отделен от инфраструктуры n8n;
- начало интервью и сохранение состояния разделены на независимые ветви Workflow.

Архитектура полностью соответствует принципу:

> Один компонент — одна ответственность.

# Что не считается ошибкой

На текущем этапе MVP отсутствие следующих компонентов не является архитектурной ошибкой:

- сохранение Process JSON;
- обработка файлов;
- Knowledge Base;
- генерация инструкций;
- генерация тестов;
- генерация учебных курсов.

Они входят в Roadmap проекта и будут реализованы позднее.

# Подтвержденные архитектурные решения

## Interview Agent полностью управляет интервью

Интервью проводит исключительно Interview Agent.

Workflow отвечает только за инфраструктуру:

- получение сообщений;
- передачу сообщений Agent;
- получение ответа Agent;
- сохранение результатов;
- отправку ответа пользователю.

Workflow не управляет логикой интервью.

---

## Process JSON

Process JSON остается единственным источником истины проекта.

Из Process JSON автоматически формируются:

- инструкции;
- тесты;
- курсы;
- база знаний;
- AI Assistant.

---

## Telegram

Telegram используется исключительно как транспорт.

Внутренняя бизнес-логика полностью независима от Telegram API.

---

## Input Gateway

Input Gateway остается единой точкой преобразования входящих сообщений в Unified Message.

---

## Business Workflow

Каждый Business Workflow отвечает только за одну бизнес-задачу.

- Navigation Workflow — навигация.
- Interview Workflow — проведение интервью.
- Learning Workflow — обучение.
- Knowledge Base Workflow — работа с базой знаний.

---

## Interview Workflow

Interview Workflow состоит из двух частей.

### Инфраструктура

- Interview Session Router
- Parse Agent Response
- PostgreSQL
- Telegram Response Router

### Бизнес-логика

Interview Agent полностью управляет интервью.

Workflow отвечает только за взаимодействие между компонентами системы.

# Unified Agent Response v1.0

Interview Agent всегда возвращает ответ в едином формате.

```json
{
  "status": "continue | completed",
  "message": "",
  "process_json": null
}
```

Workflow принимает решения исключительно на основании данного контракта.

Свободный текст LLM не используется для управления логикой Workflow.
